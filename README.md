# MiTV — деблоат и кастомный лаунчер

Проект для Xiaomi Android TV, Android 14 / SDK 34. Данные локальной сети устройства не публикуются в этом репозитории.

Кастомный лаунчер `ru.rufp.tvlauncher` (дизайн в духе двухпанельных настроек Google TV) + обратимый деблоат телеметрии/рекламы. Всё проверено скриншотами в `shots/` (00–42) и многократными перезагрузками.

## Структура

| Путь | Назначение |
|---|---|
| `tools/tv.py` | работа с ТВ: `sh <cmd>`, `keys <KEY...>`, `shot <out.png> [KEY...]` (env `TV_HOST`) |
| `tools/apkbuild.sh` | сборка APK (aapt2 + javac 8 + d8 + zipalign + apksigner), usage: `tools/apkbuild.sh launcher build/launcher.apk` |
| `tools/disable.sh` | защищённое отключение пакетов (отказывается трогать `com.android.*`, gms/gsf/webview и др.) |
| `tools/relay.py` | релей 127.0.0.1:15555 → ТВ:5555 (если adb по сети недоступен напрямую) |
| `tools/adb-closed.py` | проверка, что ADB на ТВ закрыт (порт должен отдавать Connection refused) |
| `launcher/` | исходники лаунчера (чистый SDK, без AndroidX; `src/ru/rufp/tvlauncher/*.java`) |
| `build/launcher.apk` | локальный результат сборки (не хранится в Git) |
| `backup/` | дампы до/после + `restore.sh` (полный откат) |
| `docs/` | BUILD, TESTING, REMOTE, TROUBLESHOOTING, relay.md |
| `tools/sdk`, `tools/jdk` | необязательные локальные установки тулчейна; в Git не хранятся |

## Сборка и установка лаунчера

```bash
tools/apkbuild.sh launcher build/launcher.apk
export TV_HOST=TV_IP
adb -s "$TV_HOST:5555" install -r build/launcher.apk
tools/tv.py sh 'am start -n ru.rufp.tvlauncher/.MainActivity'
```

Replace `TV_IP` with the TV's current local IP address before running the ADB commands.

Требования и настройка SDK/JDK описаны в [docs/BUILD.md](docs/BUILD.md).

Нюансы сборки:
- d8 из build-tools 34.0.0 падает с NPE на анонимных/вложенных классах в инициализаторах полей — не использовать (в коде лямбды, создаваемые внутри методов).
- `javac -source 8 -target 8 -Xlint:-options` уже прописан в `apkbuild.sh`.

## HOME-логика (важно)

- `cmd package set-home-activity` и `cmd role add-role-holder android.app.role.HOME` **сами по себе клавишу HOME не перебивают** — система резолвит дефолтный HOME через PackageManager.
- Решение: `pm disable-user --user 0 com.google.android.tvlauncher`. После этого `resolve-activity` отдаёт наш лаунчер, HOME из любого приложения ведёт в него, при загрузке система стартует сразу его (проверено 4+ перезагрузками, включая v5).
- Вернуть стоковый: `adb -s $TV_HOST:5555 shell pm enable com.google.android.tvlauncher`.

## Деблоат

- 23 пакета в `disabled-user` — список `backup/packages-disabled-final.txt`, стабильно переживает перезагрузку. Удалений не было, только disable.
- 1 пакет — `com.google.android.tvrecommendations` — **не держит disable-user**: это `UPDATED_SYSTEM_APP`, система возвращает enabled при каждой загрузке. Отключён через `cmd package suspend` — это состояние переживает перезагрузку. Обратно: `cmd package unsuspend com.google.android.tvrecommendations`.
- Private DNS: AdGuard (`dns.adguard-dns.com`) — был настроен ранее, проверено.

## Откат всего

```bash
export TV_HOST=TV_IP
backup/restore.sh   # включает 23 отключённых пакета + unsuspend tvrecommendations + подсказка по HOME
```

## Лаунчер v11 (актуальный UI; v12 медиа-панель откачена 2026-10-25)

- **v12 (медиа-панель — управление фоновой музыкой, shots/57–61) — ОТКАЧЕНА 2026-10-25:** по решению пользователя возвращена v11 — из дерева удалены `MediaListener`/`MediaCallback`/`MediaPanel`/`MediaButton` и весь медиа-код `MainActivity`, из манифеста — сервис `.MediaListener`; грант отозван (`cmd notification disallow_listener ru.rufp.tvlauncher/ru.rufp.tvlauncher.MediaListener`, проверено: `enabled_notification_listeners` пуст). Пересобрано, установлено, проверено: панели нет, док/папка/погода работают, 0 крашей. История v12: при активной `MediaSession` (Кинопоиск/Окко и т.п.) над доком появляется панель ⏮ ⏯ ⏭ в стиле дока (тёмные чипы, фокус — белая карточка). Кнопки: ВВЕРХ с дока — фокус на панель (док при этом гасится), ВЛЕВО/ВПРАВО — с закольцовкой, ОК — команда, ВНИЗ/НАЗАД — возврат на док, МЕНЮ — папка. Источник — стандартный `MediaSessionManager.getActiveSessions` + `MediaController.TransportControls` (play/pause/next/prev); сессия выбирается PLAYING→BUFFERING→PAUSED; глиф ▶/⏸ следует за состоянием воспроизведения через `MediaController.Callback`. Доступ выдаётся встроенному `NotificationListenerService` (`MediaListener`) — один раз с ПК: `adb shell cmd notification allow_listener ru.rufp.tvlauncher/ru.rufp.tvlauncher.MediaListener` (переживает перезагрузки и `install -r`, слетает при удалении пакета; тикер раз в 15 с перепрашивает список сессий и сам переподключает `setupMedia`, если доступ пропал; перезапрос также на каждом `onResume`). Панель скрыта при открытой папке и когда нет PLAYING/BUFFERING/PAUSED-сессии. Проверено end-to-end на тест-апке `ru.rufp.mediatest` (исходники в `mediatest/`, с ТВ удалена): панель появляется по появлении сессии, PAUSE/NEXT/PREV/PLAY доходят до приложения (`logcat -s mediatest`), глиф меняется после паузы, DOWN возвращает фокус на док, force-stop → панель скрывается (shots/57–61). На реальных приложениях проверено (скриншоты /tmp/rufp/{fix-1,fin-1..4}.png, логи `adb logcat -s RUFP`): **SmartTube** — фон не работал, т.к. в самом приложении стояло «Фоновое воспроизведение: Отключено» (Настройки → Общие); включено «Только аудио (по нажатию ДОМОЙ)» — при HOME сессия остаётся active=true/PLAYING, звук играет, панель ставит паузу и возобновляет с сохранением позиции (аудиотрек 0↔1 в `dumpsys audio`); **Кинопоиск** — фонового воспроизведения НЕТ по дизайну приложения: при HOME state→NONE и звук глохнет, сессия остаётся active с NONE (пикер её игнорирует — панель скрывается мгновенно, колбэк → перезапрос без ожидания тикера); скриншот DRM-плеера Кинопоиска снимается в 0 байт — норма; **Окко** — фон не поддерживается и MediaSession не публикует вовсе: трейлер карточки играет без логина (аудиотрек `ru.more.play` виден в `dumpsys audio`), но при HOME звук глохнет, а записи `ru.more.play` в `dumpsys media_session` нет ни во время воспроизведения, ни после — панель лаунчера таким приложением управлять не может в принципе (некому отправлять команды); основной контент без логина недоступен (экран «Войдите», вход по телефону/коду), тест с подпиской не проводился, но по трейлеру видно, что сессию приложение не создаёт даже при активном воспроизведении. Ранний дефект v12, из-за которого панель не появлялась и на SmartTube: перечитывания сессий были только на старте и в колбэке `onActiveSessionsChanged` (не стреляет, если список сессий не менялся), а пикер отбрасывал BUFFERING — колбэк в моменте BUFFERING/NONE оставлял лаунчер без подписки на контроллер. Грабля: сервис-листенер обязан быть **public** классом — package-private `MediaListener` валил весь процесс при биндинге (`IllegalAccessException ... not accessible from android.app.AppComponentFactory`, чёрный экран — shots/56).

## Ограничения / известное

- **Переключение входов из приложения невозможно на этой прошивке:** broadcast `android.intent.action.GLOBAL_BUTTON` — protected; в logcat фиксируется `Permission Denial: not allowed to send broadcast ... from uid=10051`. В v4 плашки «Входы/Wi-Fi/Настройки» и панель входов убраны; переключение входа — кнопкой SOURCE на пульте либо `cmd hdmi_control deviceselect <логический адрес>` с ПК.
- **Рабочий механизм переключения входа — с ПК через shell:**
  `tools/tv.py sh 'cmd hdmi_control deviceselect 4'` — Apple TV подключён по CEC как logical 0x04 (physical 0x2000 = HDMI-порт 2). В логе CEC при этом уходит `<Routing Change> 0x1000 → 0x2000`; ответ `Device Select timed out` означает лишь неполное рукопожатие и не отменяет маршрутизацию. Список устройств и их логических адресов: `tools/tv.py sh 'dumpsys hdmi_control'` (строки `CecDeviceInfo` / `display_name`).
  Возврат на Android-UI: HOME на пульте (или `tools/tv.py keys HOME`), либо кнопка SOURCE.
- Скриншоты при активном внешнем входе не показывают HDMI-картинку (Android framebuffer не содержит видеотракт) — смена входа проверяется по CEC-логу (`Routing Change`) или глазами.
- Пункт «ТВ» в панели требует `com.mitv.tvhome.michannel` (отключён) — покажет тост «ТВ-приложение недоступно».

## ADB: закрытие и переподключение

- Для проверки закрытия ADB укажите локальный адрес телевизора: `python3 tools/adb-closed.py "$TV_HOST"`.
- Для повторного подключения включите отладку по сети на ТВ, возьмите текущие адрес, pairing-порт и код с экрана ТВ, затем выполните `adb pair "$TV_HOST:<PAIRING_PORT>" <PAIRING_CODE>` и `adb connect "$TV_HOST:5555"`. Используйте ADB только в доверенной локальной сети и отключайте отладку, когда она не нужна.
- Чтобы закрыть ADB, отключите отладку по сети и беспроводную отладку в настройках разработчика, отзовите разрешения отладки и перезагрузите телевизор. Не публикуйте IP-адреса, pairing-коды и текущее состояние отладки.
- Полная настройка ADB с нуля: docs/REMOTE.md (7 нажатий на «Версию», включить отладку по сети, подтвердить RSA-запрос на ТВ).
